# Prompt and KV caching

Skippy can restore model state for an exact or shared token prefix and avoid
recomputing all repeated prefill work. This improves time to first token for
stable system prompts, tool schemas, long documents, and multi-turn chats.

Applications continue to send the complete prompt or conversation. A cache key
is optional. Skippy does not perform fuzzy or semantic prompt matching. Reuse
ends at the first token that differs.

## Cache keys

You do not need to provide a cache key for normal prefix caching. Requests
without one use the default cache namespace and can still reuse matching
prefixes automatically.

Set `prompt_cache_key` when related requests should share a dedicated cache
namespace. The value is chosen by your application. It is not generated by
Skippy, returned by a previous request, or derived from the prompt.

A cache key does not guarantee a cache hit. Requests must use the same cache
key, a compatible model and runtime, and an identical leading token sequence.

### OpenAI-compatible API

Add `prompt_cache_key` to a chat completion request:

```json
{
  "model": "Qwen3-0.6B-Q4_K_M",
  "prompt_cache_key": "support-agent:v1",
  "messages": [
    {
      "role": "system",
      "content": "You are a support agent. Follow the company support policy."
    },
    {
      "role": "user",
      "content": "How do I reset my password?"
    }
  ]
}
```

A later request can use the same key and stable system prompt with a different
user message:

```json
{
  "model": "Qwen3-0.6B-Q4_K_M",
  "prompt_cache_key": "support-agent:v1",
  "messages": [
    {
      "role": "system",
      "content": "You are a support agent. Follow the company support policy."
    },
    {
      "role": "user",
      "content": "How do I update my email address?"
    }
  ]
}
```

Skippy can reuse the matching system-prompt prefix and prefill only the changed
tail.

### Anthropic-compatible API

The Anthropic-compatible API accepts the same top-level field:

```json
{
  "model": "Qwen3-0.6B-Q4_K_M",
  "prompt_cache_key": "support-agent:v1",
  "max_tokens": 256,
  "system": "You are a support agent. Follow the company support policy.",
  "messages": [
    {
      "role": "user",
      "content": "How do I reset my password?"
    }
  ]
}
```

Anthropic `cache_control` controls retention behavior. It does not select the
cache namespace or replace `prompt_cache_key`.

### Choose a cache key

Use a stable value that represents the boundary within which prompts may be
reused:

| Use case | Example |
| --- | --- |
| One agent configuration | `support-agent:v1` |
| Tenant and agent isolation | `tenant-42:support-agent:v1` |
| Versioned tool definitions | `research-agent:tools-v3` |
| Default shared namespace | Omit `prompt_cache_key` |

Change the key when the isolation boundary or stable prompt configuration
changes.

Do not use a unique request ID, timestamp, or random value. A new value creates
a different namespace and prevents reuse from earlier requests. Do not include
secrets in the key.

Skippy trims surrounding whitespace and treats an empty key as absent.

## Default policy

`prefix_cache = "auto"` follows the admitted model-family policy. Automatic
payload selection uses the loaded graph and native memory exporters so hybrid
or recurrent models retain all required state. If no complete representation
is available, prefix reuse is disabled while inference remains available.

```toml
[cache]
prefix_cache = "auto"
prefix_cache_budget = "auto"
prefix_cache_ram = "off"
kv_cache_disk = "off"
```

## Control prompt reuse

```toml
[cache]
prefix_cache = "on"       # auto, on, off, or record
prefix_cache_budget = "8GiB"
prefix_cache_max_entries = 256
prefix_cache_min_tokens = 512
prefix_cache_stride_tokens = 128
prefix_cache_record_limit = 4
```

Use `record` to populate state without serving hits. `off` disables lookup and
recording. Exact-state snapshots are indivisible, so one snapshot may exceed a
configured soft retention target.

## Choose live KV precision

```toml
[kv]
kv_cache_type_k = "q8_0"
kv_cache_type_v = "q8_0"
kv_cache_offload = true
flash_attention = "auto"
```

Supported explicit live K/V values are `f16`, `q8_0`, and `q4_0`. Quantized V
requires compatible Flash Attention and model geometry. An incompatible
explicit choice fails rather than silently changing precision.

## Observe cache behavior

OpenAI responses report reused tokens as
`usage.prompt_tokens_details.cached_tokens`. Skippy telemetry also reports hit
status, matched prefix tokens, suffix prefill tokens, and restore source.
