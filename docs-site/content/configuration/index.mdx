# Serving configuration

Serving configuration defines how Skippy loads a model, allocates resources,
schedules requests, exposes APIs, and records reusable state. Every supported
operator control is available through `skippy serve --help`.

Use CLI options for temporary overrides and experiments. Use environment
variables for process-level deployment settings. Use `--settings serve.toml`
for a complete, reviewable serving configuration.

## Create a settings file

```toml
version = 1

[model]
model = "Qwen3-0.6B-Q4_K_M"
mmap = true

[execution]
n_gpu_layers = -1
threads = 4
batch_size = 512

[kv]
ctx_size = 8192
kv_cache_type_k = "f16"
kv_cache_type_v = "f16"

[cache]
prefix_cache = "auto"
kv_cache_disk = "off"

[scheduling]
generation_concurrency = 2
continuous_batching = true

[api]
bind_addr = "127.0.0.1:9337"
default_max_tokens = 2048
```

Run with an override and inspect the resolved launch:

```console
skippy serve --settings serve.toml --temperature 0.2
skippy serve --settings serve.toml --print-effective-config
```

## How settings resolve

Settings resolve in this order:

1. Explicit command-line options.
2. `SKIPPY_SERVE_<OPTION_NAME>` environment variables.
3. Values in the serving settings file.
4. Admitted model/stage policy and built-in defaults.

Paths in a settings file are relative to that file. Paths supplied on the CLI
remain relative to the working directory. Unknown keys, wrong sections, invalid
values, and conflicting model sources are errors.

Environment variables use the CLI representation and the
`SKIPPY_SERVE_<OPTION_NAME>` form. For example,
`SKIPPY_SERVE_THREADS=8` sets `[execution].threads`; `--threads 4` overrides it.

`--print-effective-config` reports resolved values and their sources, then
exits before loading the model or opening the listener. Skippy can still
acquire or verify local model files and plan memory. A prepared stage config
can be inspected without loading a native runtime.

## Serve multiple local models

Save this as `serving.toml` to serve two Hugging Face GGUFs on one listener.

```toml
version = 1

[[models]]
model = "Qwen/Qwen3-0.6B-GGUF:Q8_0"

[[models]]
model = "Qwen/Qwen3-1.7B-GGUF:Q8_0"
```

```console
skippy serve --settings serving.toml
```

Each entry takes exactly one source. Use `model` for the same catalog names,
Hugging Face references, and local paths accepted by `skippy serve --model`.
Skippy reuses cached artifacts and downloads missing ones during startup. Use
`model_path` to select a local GGUF explicitly. Relative paths resolve from
the settings file. In an existing multi-model file, rename `path` to
`model_path` and keep `version = 1`.

Skippy opens one listener after all models load successfully. A failed load
aborts startup and releases the models already opened. `GET /v1/models` lists
the IDs clients can send in a request's `model` field. The example uses the
full Hugging Face references as IDs. Local files default to the filename stem.
Set `id` to override a default, and use a unique ID for each entry.

Put shared tuning under `[defaults]` and per-model overrides under
`[models.settings]`. Environment variables and explicit CLI tuning options
override the same setting for every model. Specify sources in `[[models]]`
when serving a list and omit global selectors such as `[model]` and `--model`.
Set the listener with top-level `bind_addr` and the shared runtime under
`[runtime]`. `--print-effective-config` reports each model's resolved settings
and ID before native loading, and can acquire model files to prepare the report.

## Benchmark serving settings

Use `skippy tune` to compare candidate settings on a representative workload
before changing a serving configuration. Save the following example as
`sweep.json` and replace the absolute paths and runtime ID with values for your
installation. `skippy doctor --output json` reports the selected runtime ID and
cache path. The hardware identity records which machine produced the results.

```json
{
  "targets": [{"id": "demo", "path": "/models/model.gguf"}],
  "runtime": {
    "identity": "darwin-aarch64-metal",
    "bundle_dirs": ["/opt/skippy/native-runtimes"],
    "cache_dir": "/path/to/runtime-cache"
  },
  "hardware": {"identity": "local Metal workstation"},
  "workload": {
    "prompts": ["Say hello."],
    "warmup_runs": 1,
    "repetitions": 2,
    "max_tokens": 16,
    "seed": 0
  },
  "candidates": [
    {
      "context": 2048,
      "batch": 256,
      "microbatch": 128,
      "mmap": true,
      "mlock": false,
      "flash_attention": "auto",
      "speculative": {"strategy": "disabled"}
    },
    {
      "context": 2048,
      "batch": 512,
      "microbatch": 256,
      "mmap": true,
      "mlock": false,
      "flash_attention": "auto",
      "speculative": {"strategy": "disabled"}
    }
  ],
  "timeout_secs": 120
}
```

```console
skippy tune --config sweep.json
```

Each trial loads a model in its own process using the declared runtime. The
JSON report records trial failures and recommends the successful candidate
with the highest completion tokens per second for each model. A mismatched
runtime ID fails its trial. Use `--apply serve.toml` to write the winning
settings to an existing serving file after a successful one-model sweep.

| Sweep field | Requirements |
| --- | --- |
| `targets` | One or more entries with unique `id` values and absolute local model `path` values. |
| `runtime` | Expected runtime `identity`, absolute `cache_dir`, and `bundle_dirs` containing absolute paths. Optional `release` and `selection` constrain runtime selection. |
| `hardware` | Nonempty `identity` for provenance and optional `backend_device` for device selection. |
| `workload` | Nonempty `prompts`, `warmup_runs`, positive `repetitions` and `max_tokens`, and a `seed`. |
| `candidates` | Positive `context`, `batch`, and `microbatch` sizes, with `microbatch` at most `batch`. Include `mmap` and `mlock` booleans. |
| Candidate `flash_attention` | `auto`, `enabled`, or `disabled`. |
| Candidate `speculative.strategy` | `auto`, `disabled`, `native_mtp`, `ngram`, `draft_model`, or `dflash`. Include an absolute `speculative.path` for `draft_model` or `dflash`. |
| `timeout_secs` | Per-trial timeout from 1 to 86,400 seconds. |

## Configuration surfaces

| Surface | Best for | Example |
| --- | --- | --- |
| CLI | One run or a measured override | `--temperature 0.2` |
| Environment | Deployment-level process settings | `SKIPPY_SERVE_THREADS=8` |
| TOML | Versioned complete serving policy | `--settings serve.toml` |
| Sweep JSON | Isolated comparison of candidate settings | `skippy tune --config sweep.json` |
| Admitted stage plan | Planner-owned split identity and tensor closure | `--config stage-0.json` |
