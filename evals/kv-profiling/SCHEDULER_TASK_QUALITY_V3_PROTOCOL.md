# Held-out chat quality and fixed-output performance qualification, version 3

Registered before any version 3 model response or timed cell. The version 1
exact-text failures and version 2 quality failure remain unchanged. Version 2's
first Qwen3.5 vanilla control completed 256 requests but scored 0/256 because
raw continuation with forced 32 tokens did not produce final answers. Two
unscored 16-item chat probes then showed that default thinking spent the
entire 32-token budget on reasoning, while disabling thinking yielded 8/16
answers at 523 input tokens. A complete **unscored** nonthinking chat replay of
the original 256 tasks yielded 139/256 correct (64 arithmetic, 64 extraction,
9 ordering, 2 assignment) at 523 input tokens. The
[compact evidence record](pr-evidence/task-quality-chat-pilots.json) cites
its local independent audit SHA256
`7d8d18dd2cd015ef70c01b8bda209efbb0890a21698254ff99acdc51e619a981`.
None of those runs counts toward version 3. The 139/256 result shows why the
previous 200-correct prerequisite could not pass on a 256-item fixture even
with a usable answer path. This version retains all four task types and their
difficulty rules, uses a wholly new seed, and doubles the unique task count.
The held-out task values and scoring rules below may not change after the
first version 3 model result. A failed gate is retained as a failure.

shards in `ci/inference-artifacts.json`: Qwen3.5-4B,
Qwen3-Coder-30B-A3B, Qwen3.6-35B-A3B and Qwen3.8-Flash-Next. Compare the
current PR Skippy server and qualified native Metal bundle with both pinned
vanilla llama.cpp layouts. The original Skippy arm is a diagnostic. Run on
`macstudio-2l0352` at $0 with 16 lanes of 8192 tokens, F16 K/V, logical and
microbatch 512, full Metal offload, prefix and disk caches off, and measured
memory headroom. No model, weights, precision, runtime, backend, shard, or
source substitution or download is allowed. Seal source tree, binary, native
bundle, model, prompt, request and artifact SHA256 identities per job. A model
that cannot meet the configuration is capacity-blocked.

## Quality request and score

For each model, use the pinned vanilla model's live `/apply-template` and
`/tokenize` endpoints to materialize each user-message prompt to **512
effective tokens including the chat template** with
`chat_template_kwargs: {"enable_thinking": false}`. Preserve the unchanged
task after neutral padding, every rendered-token digest and the prompt SHA.
Calibrate whether native tokenization of the rendered template adds a special
token using one fixed, unscored, non-task chat request per model, record both
tokenizer counts and actual `usage.prompt_tokens`, and select only a matching
mode. A calibration failure blocks that model; calibration output is never
scored. The model-specific prompt archive is sealed after calibration and
before any scored task output.
Seal the 512 model-specific prompts before any scored response. Check actual
`usage.prompt_tokens == 512` independently on both vanilla layouts and
Skippy; a shape mismatch blocks that arm. Do not silently switch endpoint or
reduce the context target. The same request body, except model alias, goes to
each arm: `/v1/chat/completions`, one user message, `max_tokens: 32`,
`temperature: 0`, `seed: 42`, `top_p: 1`, `top_k: 0`, `min_p: 0`,
`repeat_penalty: 1`, `cache_prompt: false`, nonstreaming, and the above chat
template kwargs. `ignore_eos` is absent; one to 32 output tokens are valid.
Require empty `reasoning_content` and retain raw `content`, usage,
finish reason and full request. An unparseable final nonempty line is wrong;
the only accepted answer is the registered integer on that line, optionally
prefixed by `ANSWER:`. No posthoc answer extraction is permitted.

Score quality separately at single, c64, c128 and c256 offered concurrency.
At each level use all 512 unique tasks, in a deterministic SHA256 ordering of
task IDs sealed with the prompt archive. For c64/c128/c256 send 8/4/2 waves
of that level respectively, with equal scheduled zero offset within each
wave, and preserve actual arrivals. Use a fresh process per arm and repeat,
reverse the arm order on the repeat, and run a fresh A/A of each vanilla
layout. Require 512/512 complete, zero cache use and nominal thermal and
contention gates per arm. At c256 explicitly set a 256 waiting-request
capacity on both Skippy arms; the default queue remains unchanged.

For each comparator require at least **200** correct baseline items. Count
an adverse task only if that comparator is correct and current Skippy is
wrong. Its one-sided exact 95% Clopper–Pearson upper bound must be **strictly
below 2%**; a lower bound above 2% is FAIL, and a crossing interval is
UNPROVEN. Apply the same bound to each vanilla A/A repeat. Candidate parsed
answers must be identical across its repeats for all 512 IDs; preserve raw
text differences. Publish per-stratum baseline-correct and adverse counts;
the aggregate bound makes no separate quality claim for a stratum with few
baseline-correct items. Nonfinite logits/logprobs, incomplete responses,
missing IDs, invalid token counts, cache hits or candidate instability fail.
Qwen3.6's archived confident numerical divergence still needs a measured
mechanism or pinned independent reference; aggregate task scores alone do not
resolve it. Exact cross-engine text differences remain recorded as failures
under version 1 and as diagnostics here.

## Separate fixed-output performance workload

To keep tokens/sec comparable, run the original sealed fixed-32-output
inferencekit 0.1.1 benchmark as a **separate** workload after the same-model
quality gate passes. Keep its exact model-specific fixture, registered
single-user screen and c64/c128/c256 offered-request counts, generation
settings, zero caches, full Metal and frozen single-user reference per model.
Run four balanced fresh-process rounds of the original, current Skippy, and
both vanilla layouts at single, c64, c128 and c256; use equal cooldown and one
equal longer-cooldown retry only for thermal or contention invalidation.
Never selectively retry a correctness, completion or performance failure.

For each level and vanilla layout, report four paired ratios and the full
4^4 empirical paired-bootstrap two-sided 95% interval for aggregate output
tokens/sec and p95 TTFT, E2E and TPOT. Throughput's lower bound must exceed
0.98, and every latency upper bound must be below 1.02. A bound crossing the
margin is UNPROVEN. Independently report TTFT p95 <=30 seconds, TPOT p95 <=1
second and zero failed requests per arm and level. Favorable relative timing
cannot turn an absolute SLO failure into a pass. Retain every exact-text
difference and report quality and performance as distinct workload results.
No version 3 performance cell may be promoted as a four-model claim without
all four model-specific quality and timing gates. Publish four per-model
tables with counts, tokens/sec, TTFT, E2E, TPOT, intervals, quality,
exact-text and capacity verdicts. Historical Thoughtworks indices 16/227
and older hybrid-MoE discrepancies remain unresolved unless directly replayed.
